Where this endsDay 1

A live weather station, from one Broker

Coreflux asks a weather service for this site, turns the answer into one reading, raises a heat alert when it gets too hot, keeps the history, emails the team and shows it on a live dashboard.

What it does

  • Polls the Open-Meteo weather API every 60 seconds (or on demand)
  • Converts °C to °F and packages a clean WeatherReading
  • Raises a heat alert against a threshold you can change live
  • Logs every reading to CSV and emails the team on heat alerts
  • Displays everything on a live dashboard

The pathFour moves

Get it, hold it, work on it, send it

The antenna pulls the weather in, every reading lands on a stud, the bricks convert and decide inside the Broker, and the result goes to the box, the file and the mail.

The BrokerPiece 1 of 7

The Broker is the baseplate

Every piece you deploy sticks to it, and the LoT you write runs on it. Devices, apps and your logic all connect here.

On your machine

  • One Broker container running locally
  • The Coreflux HUB at http://localhost:3000 is your browser workspace
  • Broker, HUB, Mailpit (test inbox), and the weather-station project start together
terminal

docker compose up -d
docker compose wait load-project

TopicsPiece 2 of 7

Topics are the studs

A stud is where a piece clicks on, and the same stud is how two pieces connect. One piece publishes to a topic, and every piece listening on that topic picks it up. The publisher never needs to know who is listening.

campus/
weather/
request publish "poll" here to trigger an immediate fetch
fetch RequestWeather publishes the query string here
raw the Open-Meteo JSON response lands here
reading the clean, converted WeatherReading JSON
alerts/heat_active HeatAlert's retained state: "on" or "off"
alerts/heat fires once when a heat wave starts; triggers the email
config/
heat_limit_c retained threshold in °C (default 30)

The studs sit in a hierarchy you read like a folder path. That hierarchy is your Unified Namespace (UNS). In MQTT wildcards, + matches one level and # matches everything below it.

ActionsPiece 3 of 7

An Action is one brick, one job

It starts on a trigger: a timer (ON EVERY ...) or a message arriving on a topic (ON TOPIC ...). The weather station uses four.

The four Actions

  • Heartbeat (Lab 1) runs every 5 seconds so you can see the Broker is alive
  • ProcessWeather (Lab 2) runs when raw JSON arrives, converts °C to °F, and publishes the Model
  • RequestWeather (Lab 3) runs every 60 seconds (or on campus/weather/request) to ask for weather
  • HeatAlert (Lab 4) compares the temperature to config/heat_limit_c and raises an alert
LoT
DEFINE ACTION Heartbeat
ON EVERY 5 SECONDS DO
    PUBLISH TOPIC "campus/weather/heartbeat" WITH "ok"

DEFINE ACTION HeatAlert
ON TOPIC "campus/weather/reading" DO
    SET "temp_c" WITH (GET JSON "temperature_c" IN PAYLOAD AS DOUBLE)
    SET "limit" WITH (GET TOPIC "config/heat_limit_c" AS DOUBLE)
    SET "active" WITH (GET TOPIC "campus/weather/alerts/heat_active" AS STRING)
    IF {temp_c} > {limit} THEN
        IF {active} != "on" THEN
            KEEP TOPIC "campus/weather/alerts/heat_active" WITH "on"
            PUBLISH TOPIC "campus/weather/alerts/heat" WITH PAYLOAD
    ELSE
        KEEP TOPIC "campus/weather/alerts/heat_active" WITH "off"

KEEP TOPIC publishes a retained message, so heat_active remembers whether an alert is already active. That way, the email on campus/weather/alerts/heat is sent only once when a heat wave starts (project/01-heartbeat.lotnb to 04-heat-alert-history-email.lotnb).

ConnectorsPiece 4 of 7

A Connector is the piece with an antenna

It reaches outside the Broker: a web API, a CSV file, an email server, a PLC, or a database. The weather station uses three.

The three Connectors

  • CampusWeather (TYPE REST, Lab 3): calls Open-Meteo and publishes JSON to campus/weather/raw
  • WeatherHistory (TYPE CSV, Lab 4): appends every reading to campus-weather.csv
  • HeatMail (TYPE EMAIL, Lab 4): sends an HTML alert email to Mailpit
LoT · Broker 2.22.0
DEFINE CONNECTOR CampusWeather WITH TYPE REST
    ADD REST_CONFIG
        WITH BASE_URL "https://api.open-meteo.com"
        WITH TIMEOUT 10
        WITH VERIFY_SSL TRUE
    ADD EVENT FetchCurrent
        WITH SOURCE_TOPIC "campus/weather/fetch"
        WITH DESTINATION_TOPIC "campus/weather/raw"
        WITH METHOD "GET"
        WITH ENDPOINT "/v1/forecast"
        WITH QUERY_PARAMS_FROM_PAYLOAD TRUE

RequestWeather reads WEATHER_LAT and WEATHER_LON via GET ENV and publishes the query string to campus/weather/fetch. CampusWeather calls Open-Meteo and publishes the response to campus/weather/raw.

ModelsPiece 5 of 7

A Model is one brick per field

The manual says which brick comes next. Each brick is one field and the color is its data type, so every reading published on campus/weather/reading has the exact same JSON shape.

WeatherReading (Lab 2)

  1. station (STRING, constant "campus-main")
  2. temperature_c, temperature_f, and wind_kmh (DOUBLE)
  3. weather_code (INT) and observed_at (STRING, UTC timestamp)
  4. ProcessWeather populates the sub-topics and runs PUBLISH MODEL WeatherReading
LoT
DEFINE MODEL WeatherReading COLLAPSED
    ADD STRING "station" WITH "campus-main"
    ADD DOUBLE "temperature_c" WITH TOPIC "campus/weather/reading/temperature_c"
    ADD DOUBLE "temperature_f" WITH TOPIC "campus/weather/reading/temperature_f"
    ADD DOUBLE "wind_kmh" WITH TOPIC "campus/weather/reading/wind_kmh"
    ADD INT "weather_code" WITH TOPIC "campus/weather/reading/weather_code"
    ADD STRING "observed_at" WITH TIMESTAMP "UTC"

COLLAPSED bundles all fields into one flat JSON payload when ProcessWeather runs PUBLISH MODEL WeatherReading TO "campus/weather/reading" (see project/02-model-processweather.lotnb).

RulesPiece 6 of 7

Rules are the building frame

The frame keeps pieces off the studs they do not belong on. A Rule decides which users may publish or subscribe to which topics.

In the weather station (Lab 5)

  • Everyone can read the weather topics
  • Only root can publish to config/# (including config/heat_limit_c)
  • Any publish to config/# from another user (like bob) is silently dropped
LoT
DEFINE RULE ProtectWeatherConfig WITH PRIORITY 1 FOR PublishToBroker
    IF USER IS NOT "root" AND TOPIC MATCHES "config/#" THEN
        DENY
    ELSE
        ALLOW

Lower priority numbers run first: PRIORITY 1 is evaluated before the default AllowAll rule (priority 100). Custom Rules require an event licence (activate your CFLX-… code in Broker Settings → License); on Community Edition you can read along and continue to Lab 6.

PanelsPiece 7 of 7

A Panel is the box

The box shows the finished build. A Panel is a live operator dashboard defined in LoT and rendered in the HUB's Dashboards window — with stat cards and badges bound directly to MQTT topics.

LoT
DEFINE PANEL CampusWeather
    WITH TITLE "Campus Weather"
    WITH ICON "cloud-sun"
    WITH REFRESH 5

    LAYOUT USING GRID WITH COLUMNS 12
        SECTION "Current Conditions" WITH ICON "thermometer" COLLAPSIBLE FALSE
            WIDGET "Temperature (°C)" AS STAT
                WITH SOURCE TOPIC "campus/weather/reading/temperature_c"
                WITH UNIT "°C"
                WITH DECIMALS 1
                WITH SPAN 4

project/06-panel.lotnb adds the °F card, Wind Speed card, and a Heat Alert BADGE widget that switches between green (Normal) and red (HEAT ALERT).

DEFINE THINGStretch Goal 6

The whole station as one Thing

In Broker 2.22 (technical preview), you can bundle properties, a CONNECTOR, a MODEL, and ON EVERY / ON TOPIC logic into a single Thing definition.

LoT · Broker 2.22.0
DEFINE THING CampusStation
    WITH DESCRIPTION "Campus weather station"
    PROPERTY "station_id" TYPE STRING DEFAULT "campus-main"
    PROPERTY "temperature_c" TYPE DOUBLE UNIT "°C"
    PROPERTY "temperature_f" TYPE DOUBLE UNIT "°F"

    CONNECTOR OpenMeteo TYPE REST
        WITH BASE_URL "https://api.open-meteo.com"
        ADD EVENT FetchCurrent
            WITH SOURCE_TOPIC "campus/weather/thing/fetch"
            WITH DESTINATION_TOPIC "campus/weather/thing/raw"
            WITH METHOD "GET"
            WITH ENDPOINT "/v1/forecast"
            WITH QUERY_PARAMS_FROM_PAYLOAD TRUE

    MODEL Reading COLLAPSED
        ADD STRING "station" WITH {station_id}
        ADD DOUBLE "temperature_c" WITH {temperature_c}
        ADD DOUBLE "temperature_f" WITH {temperature_f}

    EMITS Reading TO "campus/weather/thing/reading"

Labs 1–6 build the station piece by piece so you learn each building block. Once you finish Lab 6, open project/07-stretch.lotnb to try deploying the complete DEFINE THING CampusStation!
